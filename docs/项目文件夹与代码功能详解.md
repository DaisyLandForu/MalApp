# test1 项目文件夹与代码功能详解

本文档用于说明 `test1` 本地 MVP 项目的目录结构、每个文件夹的作用、每个主要代码文件实现了什么功能，以及这些代码在“恶意 APP 研判引擎”里承担什么角色。

## 一、整体功能概览

当前 `test1` 实现的是一个本地可运行的恶意 APP 研判 MVP。

它的完整处理链路是：

```text
360/cm Excel 数据
  ↓
导入 SQLite 数据库
  ↓
按 MD5 合并成样本
  ↓
四个智能体生成证据块
  ↓
模型甲 / 模型乙基于证据进行多轮辩论
  ↓
仲裁器生成 Engine C
  ↓
WEC 融合 Engine A、Engine B、Engine C
  ↓
输出最终研判结果
  ↓
前端页面展示结果和历史记录
```

当前模型说明：

- Engine A：360 引擎结果。
- Engine B：cm 引擎结果。
- Engine C：四智能体 + 本地 Qwen2.5-0.5B + 仲裁器生成的结果。
- 模型甲：本地 Qwen2.5-0.5B，通过“保守复核”提示词扮演。
- 模型乙：本地 Qwen2.5-0.5B，通过“风险优先”提示词扮演。
- 四个智能体：当前是规则证据智能体，不是四个独立大模型。

### `engine/evaluate_params.py`

作用：

在弱标注数据集上评估参数组合，帮助选择 WEC 和阈值参数。

它不会对 1 万多条样本逐条调用 Qwen，因为那样太慢。它使用一个快速近似的 Engine C 分数。

核心参数类：

```python
@dataclass(frozen=True)
class Params
```

包含：

```text
malicious_threshold：判恶意的阈值
suspicious_threshold：判可疑的阈值
engine_c_weight：Engine C 的权重
conflict_boost：引擎分歧时给 Engine C 的加分
```

主要函数：

```python
load_jsonl(path, limit=None)
```

读取 JSONL 数据集。

```python
feature_score(sample, conflict_boost)
```

用结构化字段快速模拟 Engine C 分数。

会看：

- 360/cm 是否分歧。
- 是否仿冒。
- 是否有诈骗家族。
- 是否有 URL、邮箱、手机号等情报字段。
- 是否加壳。
- 描述里是否有风险关键词。

```python
predict(sample, params)
```

用一组参数预测最终结论。

融合公式：

```text
final_score = (engine_a + engine_b + engine_c * engine_c_weight) / (2 + engine_c_weight)
```

```python
score_result(rows, params)
```

计算一组参数在数据集上的效果。

指标包括：

- accuracy
- malicious_precision
- malicious_recall
- risk_precision
- risk_recall
- confusion matrix

```python
param_grid()
```

生成候选参数组合。
