MalApp 四智能体与双模型输出同质化问题修复说明

一、问题原因
1. 冲突样本 Excel 主要包含 MD5、引擎甲/乙评分、应用名称和病毒名称，
   不包含 APK 权限、签名、域名、图标等完整领域特征。
2. 旧版本没有把“应用名称_cm”“病毒名称_cm”等引擎专属列提升为四智能体
   可直接读取的通用字段，导致不同样本进入领域分析后的有效差异很少。
3. 旧版本网络 IOC 扫描范围过大，会把 MD5、病毒名称中的字符串误识别为域名或 C2。
4. 本地 Qwen2.5-0.5B 容量较小，并且甲乙使用同一模型、确定性生成。
   它直接复述了提示词中的 JSON 示例，把 score 固定输出为 0.0，并输出
   “定向质疑”“证据化回应”等占位文本。
5. 旧错误结果已进入历史缓存，若不升级缓存版本，相同样本会继续复用旧报告。

二、已经修复
1. 正确映射中文 Excel 表头，并派生应用名称、病毒名称、引擎标签和评分差。
2. 四智能体现在会读取引擎冲突、应用名称和病毒家族证据。
3. 网络 IOC 只扫描真实网络字段，不再扫描 MD5 和整条 JSON。
4. 业务标签只扫描业务相关字段，不再因 MD5 中偶然出现“c2”产生误判。
5. Qwen 输出如包含占位符、非法枚举或不合理的固定 0 分，会被判定为无效；
   系统随后使用该样本真实证据生成甲乙差异化结果。
6. 质疑和反驳会显示对方分数、实际证据块和本轮调整值。
7. 终审摘要显示甲乙分数、最强证据、平均证据和最终校准值。
8. 分析缓存版本已升级，旧错误缓存不会被新版本命中。

三、如何重新研判原来的十条数据
1. 打开“MalApp_Hermes同质化修复版.exe”。
2. 在“数据加载”中重新选择原来的“冲突样本分析.xlsx”。
3. 传输数量设置为 10，完成导入。
4. 在自动研判流水线中选择新产生的批次，研判数量设置为 10。
5. 启动研判。旧报告仍保留用于对比，新报告会按修复后的逻辑生成。

四、结果仍可能部分相同的情况
如果多个样本提供的领域证据完全相同，例如都只有 0 对 100 的引擎冲突，
而没有权限、签名、域名、图标或包名，那么静态智能体的部分风险分数相同是合理的。
系统不会为了制造差异而随机修改置信度；它只根据实际输入证据产生差异。
